1 · Architectural principles

#PrincipleConsequence
1Browser-only, fully offlineNo server runtime. All data in IndexedDB. PWA service worker for asset caching.
2Workers do heavy workSeeding and live ticks run off the main thread to keep the UI at 60 fps.
3Tiles are self-containedEach dashboard tile owns its own data hook, loading state, error boundary.
4Density over decorationEvery pixel earns its place — Bloomberg / SOC dashboard aesthetic.
5No TypeScript, but typed-feelingJSDoc @typedef + PropTypes for editor autocomplete and runtime validation.
6Auditable by defaultEvery data access goes through a single audit() helper.
7RBAC at the boundaryPermissions checked at route guards and action handlers, not deep inside components.

4 · Runtime data flow

DIAGRAM 4.1 · Boot, live, snapshot, and audit data paths

Three concurrent paths

  • Boot path (one-shot, green) — BootSplash → seed worker → Dexie → ready flag.
  • Live path (continuous, cyan) — tick worker → main thread → liveStore → tiles. Persistence is fire-and-forget.
  • Snapshot path (lazy, green) — tiles call useDexie on mount; results memoized until deps change.
  • Audit path (cross-cutting, magenta) — any access calls audit() which writes to Dexie.

7 · State management

Three Zustand stores. None of them subscribe to Dexie directly — that responsibility lives in hooks.

StoreOwnsPersistence
authStore user, login(), logout() localStorage key atlantis.auth
uiStore nav collapse, inspector open, palette open in-memory only
liveStore rolling event feed (200), rolling anomalies (80), 60-sample sparklines, cumulative metrics in-memory; re-hydrated by tick worker

Why Zustand and not Context?

  • Tile re-render granularity. Selectors mean a tile only re-renders when its slice changes.
  • No provider tree boilerplate.
  • Middleware hooks (persist) are first-class.

Anti-patterns we explicitly avoid

  • Reading the entire entities table on render — only the inspector / dashboard does bounded reads.
  • Cross-component prop drilling for live data — every consumer subscribes to liveStore.
  • Heavy chart libs on first paint — react-force-graph-2d is dynamically imported by the GraphPreviewTile.

11 · Security model

ATLANTIS is offline-first, so the threat model is bounded but not empty. Risks:

RiskMitigation
Operator with browser access can read IndexedDB rawTreat the host machine as a trust boundary; encrypt at rest with FDE.
XSS via injected entity nameReact escapes by default; no dangerouslySetInnerHTML anywhere.
Stale role after revocationRoles re-read every 3s by useRoles; Phase 2 adds an in-app force-reauth.
Audit tamperingAudit is append-only via Dexie auto-increment; Phase 3 adds a hash-chain.
Service-worker cache poisoningHTML uses NetworkFirst so a fresh bundle always supersedes cache when online.

12 · Extensibility & roadmap

Adding a new tile

  1. Create src/components/tiles/MyTile.jsx using <Tile title=… live? footer=…>.
  2. Get data via useDexie (snapshot) or useLiveStore (live).
  3. Export from src/components/tiles/index.js.
  4. Place it on the grid in src/features/dashboard/Dashboard.jsx with a span="col-span-N row-span-M" class.

Adding a new screen

  1. Create src/features/<screen>/Screen.jsx.
  2. Register a <Route> in src/App.jsx under the Protected shell.
  3. Add a nav entry in src/features/shell/LeftNav.jsx.

Adding a new permission

  1. Add to ALL_PERMISSIONS in src/lib/rbac.js with its group.
  2. Bump built-in role definitions if appropriate.
  3. Add gate logic at the call site via can(user, roles, 'your_perm').
