1 · Introduction

ATLANTIS is a self-contained, browser-based fraud-intelligence workbench. It runs entirely offline: no server calls, no telemetry, no external dependencies once the application bundle is cached. All data lives in IndexedDB on the operator's machine.

Who this manual is for

  • Analysts — daily monitoring of the dashboard and entity browsing.
  • Investigators — opening cases, deeper relationship exploration, exports.
  • Admins — managing operators, roles, and the data sources panel.

2 · The application shell

Every screen sits inside the same four-region shell. Learn the regions once and the rest of the UI is self-explanatory.

DIAGRAM 2.1 · Application shell, four regions

1 — Top bar

Brand on the left, global search + command palette trigger in the middle, live stream & alert counters on the right, then the operator avatar with a sign-out control.

2 — Left navigation

Persistent vertical rail. The active route gets a cyan accent stripe. The set of visible items is filtered by your role's permissions (Phase 2 will hide items you cannot use; today every link is visible but protected screens redirect).

3 — Main content

The active screen. Each screen owns its own internal layout — typically with left-rail facets, a center workspace, and a right-side inspector.

4 — Bottom status bar

System telemetry at a glance: connection state, record counts, ingestion delta, system load, query latency, current operator, keyboard hints, and UTC clock.

3 · Roles & permissions

ATLANTIS ships with three built-in roles and a builder for unlimited custom roles. Every screen and every action is gated by one or more permissions; if your role is missing a required permission, the UI element is hidden or returns an "Insufficient permission" error.

DIAGRAM 3.1 · Role × permission matrix

Custom roles

Admins can compose any subset of the nine permissions into a named role. Common patterns:

  • Read-only Auditor — all view_*, nothing else.
  • Compliance Reviewer — Investigator powers minus export_data.
  • Power Analyst — Analyst + edit_entities.

Custom roles are persisted in IndexedDB and survive page reloads. They appear alongside built-ins on the login screen.

4 · Sign-in & session

The login screen has three controls: operator name, role selection, and a deep-link to the custom role builder.

DIAGRAM 4.1 · Login screen with role selection

Sign-in steps

  1. Type your operator name (this is what will appear in the audit log).
  2. Select a role. Custom roles you've defined appear in the same list, tagged with a custom chip.
  3. Click ENTER →. You'll land on the Dashboard.
Session is persisted in localStorage under atlantis.auth. Closing the tab leaves you signed in next time. To force re-auth, click the power icon in the top-right of the top bar.

6 · Entity Explorer

The Entity Explorer is a faceted, virtualized browser over the 50,000+ seeded entities. It is the primary tool for ad-hoc investigation and the entry point to the inspector.

DIAGRAM 6.1 · Entity Explorer (facets, table, inspector)

Working with facets

  1. Click any chip to toggle that filter on / off.
  2. Multiple chips in the same group form an OR; across groups they form an AND.
  3. Risk range narrows the result set by composite risk score.
  4. The search box matches by entity name or ID prefix.

The inspector

Clicking any row opens the right-side inspector with:

  • Core attributes (type, country, risk bar, created/updated timestamps).
  • Type-specific fields (DOB for persons, balance for accounts, etc.).
  • Up to 10 most recent related events.

Every inspector open emits an audit entry: view_entity.

7 · Graph View

The Graph View is a full-screen, force-directed canvas for exploring the relationship network. It is reached from the left nav (GRAPH) or via the command palette. Access requires the view_relationships permission.

Layout

RegionPurpose
Top barLive node / edge counts and the layout picker — FORCE, RADIAL, GRID.
Left railEdge-kind toggles, the risk slider, and the edge-limit slider. A colour legend mirrors the edges on the canvas.
CanvasNodes coloured by risk (cyan / amber / red) and sized by risk + degree. Transaction edges animate with directional particles.
Right inspectorSelected node's attributes, risk, degree, and up to 30 neighbours. Click any neighbour to re-centre on it.
Bottom scrubberFilters edges by firstSeen ≤ T across a rolling 180-day window. Drag right to reveal newer relationships.

Edge kinds

Six relationship types can be toggled independently:

  • transacts_with, owns, controls
  • communicates_with, co_located, shares_device
Performance. The graph engine (react-force-graph-2d) is dynamically imported, so the canvas only loads when the route opens. Keep the edge limit under 400 on lower-end machines; the slider tops out at 800.
Audit. Every node selected on the canvas emits a view_node entry with context: graph — visible in both the Recent Audit tile and the dedicated Audit Log screen.

8 · Investigation Workspace

Cases bundle entities, notes, and evidence into one persistent investigation record. The workspace has two views: a list at /investigations and a detail view at /investigations/:id. Both require the open_investigations permission.

List view

  • Status filter chips: all open reviewing closed.
  • Columns: status, title (linked), entity count, progress bar, last-updated, created-at.
  • Click + NEW CASE (top right) to prompt for a title and open a fresh case. The action emits an open_case audit entry.

Three-column detail

ColumnContents
Left — EntitiesList of entities pinned to the case. Add by entering an entity ID (e.g. E000123) and pressing +. Hover a row to reveal the × remove control.
Centre — NotesReverse-chronological note timeline with author + relative timestamp. Draft a note in the bottom composer; ⌘↵ / Ctrl ↵ posts it.
Right — EvidencePinned event references. Use + PIN LAST EVENT to attach the most recent live event from the tick worker as evidence.

Top bar controls

  • Status chips — switch between open, reviewing, closed.
  • Progress slider — 0–100%; mirrored on the list view's progress column.
Audit. Every status change, progress edit, note, entity add / remove, and evidence pin writes an edit_case entry with a structured diff in details.

9 · Audit Log screen

The dedicated Audit Log screen (/audit) is the forensic counterpart to the dashboard's Recent Audit tile. It loads up to 5,000 most-recent rows from the local audit store and lets you filter, search, and export them. Access requires view_audit; export requires export_data.

Controls

ControlEffect
Range chips15M, 1H, 24H, 7D, ALL — windows the table to entries newer than the chosen offset.
Operator searchFree-text filter against userId; case-insensitive substring match.
Action facet (left rail)Multi-select chips for login, view_entity, create_role, edit_role, delete_role, export_audit, run_query, open_case, edit_case, close_case.
EXPORT CSVDownloads the currently-filtered rows as atlantis-audit-YYYY-MM-DD.csv. The export itself emits an export_audit entry with the row count.

Columns

  • Timestamp — local-clock, monospace.
  • Operator — userId or system.
  • Action — colour-tagged action name.
  • Target — affected object ID, when applicable.
  • Details — inline JSON payload.
Operators without export_data still see the EXPORT CSV button, but it renders disabled with a tooltip explaining the missing permission — clearer than hiding the affordance entirely.

11 · Anomaly Tuning

The Anomaly Tuning workspace (/anomalies) lets analysts shape the weighted-signal model that flags suspicious entities, preview its effect on a 500-entity sample, and persist or apply the resulting detections. Access requires view_events.

Layout

RegionPurpose
Top barLive model name, live flagged / scanned (%) readout, and the action buttons RESET, ★ SAVE, APPLY → ANOMALIES.
Left railOne slider per signal (weight 0–1) plus a threshold slider (flag composite ≥ N). Below: the list of saved model configs — click to load, hover for × delete.
CentrePreview of the top 30 scored entities. Each row shows the entity, composite risk bar, FLAGGED/BELOW chip, and per-signal contribution chips.
Right railReverse-chronological list of the most-recent anomaly rows written into the persistent store.

Signals

Signals are defined in src/lib/anomalyModel.js. Each contributes to the final composite score weighted by its slider. Setting a weight to zero excludes that signal entirely from scoring.

Saving and applying

  • ★ SAVE prompts for a name and persists the config to modelConfigs with a save_model audit entry.
  • APPLY → ANOMALIES writes up to 40 flagged entities into the anomalies store, classifying severity by composite score (≥85 critical, ≥70 high, ≥60 medium). Emits apply_model with the row count.
  • RESET restores defaultConfig() without touching saved models.
Toasts. Save / apply / load / delete operations confirm via the toast layer in the bottom-right. Errors and "no rows crossed threshold" cases surface there too.

13 · Query language

A compact, chip-friendly expression language drives the Entity Explorer's advanced filter and the Report Builder's query section. Implementation lives in src/lib/query.js.

Grammar

query        := clause (WS clause)*
clause       := field ":" value
field        := "type" | "country" | "tag" | "risk" | "name" | "id"
value        := comparison | range | list | string
comparison   := (">"|"<"|">="|"<="|"=") number
range        := number ".." number
list         := value ("," value)+
string       := unquoted | "quoted with spaces"

Fields

FieldOperatorsExample
typeeq, intype:person,organization
countryeq, in (ISO codes, case-insensitive)country:RU,CN
tageq, intag:sanctioned,pep
riskeq, gt, lt, gte, lte, rangerisk:>80 · risk:60..100
namecontains (case-insensitive)name:"halcyon holdings"
idcontains (upper-cased)id:E000ABCD

Clause combining

Whitespace-separated clauses are AND-combined. There is no explicit OR; use a comma-list inside a single clause for disjunction within one field. Unknown fields and malformed numeric values surface as parse errors in the errors array returned by compileQuery(); the UI shows them inline as red chips.

Saved queries. The Entity Explorer's ★ button stores the current query string against a chosen name; the dropdown reloads them instantly. Saved queries are scoped per-operator and never leave the browser.

14 · Admin & custom role builder

Admins reach this screen from the left nav or by clicking "⚙ Define a custom role" on the login screen. It is split in two: a roster of all roles on the left, and an editor on the right.

DIAGRAM 7.1 · Custom role builder, permissions grouped READ / WRITE / ADMIN

Creating a custom role

  1. Leave the role list with no row selected (the editor shows "NEW ROLE").
  2. Type a name and a one-line description.
  3. Click permissions to toggle them on / off. Each group counter updates live.
  4. Click SAVE. The role is persisted to IndexedDB and appears on the login screen for everyone.

Editing or deleting a role

Click EDIT on any role to load it into the editor. System roles can be edited but not deleted (the DEL button is hidden). Custom roles can be fully removed; existing operators with that role will fall back to the lowest-power role on next sign-in.

Audit. Every role create / edit / delete writes to the audit log with the actor's ID and the permission count of the resulting role.

15 · Command palette & shortcuts

Open the palette with ⌘K (mac) or Ctrl K (Windows / Linux). It does three things:

  • Navigate — fuzzy-match any screen name. Registered routes: Dashboard, Entity Explorer, Graph View, Investigations, Admin / Roles. Geospatial, Anomaly Tuning, and Report Builder are reachable via the left nav.
  • Search entities — name or ID, top 8 by risk.
  • Run actions — registered commands; Phase 4 expands the registry (chord shortcuts, saved-query recall).

16 · Common workflows

DIAGRAM 9.1 · End-to-end alert → escalation flow with role hand-offs

Workflow A — Triage a critical anomaly

  1. From the Dashboard, the Anomalies tile shows a fresh CRIT row.
  2. Note the entity ID (last column of the row). Press ⌘K, paste the ID.
  3. Hit ↵ to jump to Entity Explorer with the row pre-focused.
  4. Inspector opens automatically — review attributes and last 10 events.
  5. If suspicion confirmed, jump to Investigations, click + NEW CASE, and add this entity to the case from the left rail.

Workflow B — Search for an entity by name

  1. Open the palette (⌘K).
  2. Type any subsequence of the name (e.g. hlcn matches "Halcyon Holdings").
  3. Press ↵ on the top result.

Workflow C — Define a new role and assign it

  1. Sign in as Admin.
  2. Go to Admin → Roles. The editor shows "NEW ROLE".
  3. Name it, describe it, toggle the permissions you want.
  4. Click SAVE. Sign out.
  5. On the login screen, your custom role is now selectable.

17 · Audit & compliance

Every read of an entity, every role change, every login, every case edit, every graph node selection, and every CSV export writes an entry to the audit object store in IndexedDB. The full trail is browsable and exportable from the Audit Log screen.

FieldTypeNotes
idauto-incrementPrimary key.
userIdstringThe signed-in operator's ID, or 'system'.
actionstringlogin, view_entity, view_node, view_cluster, open_case, edit_case, close_case, export_audit, save_model, delete_model, apply_model, cache_tiles, save_report, print_report, create_role, …
targetstring?The affected object's ID, when applicable.
detailsJSON?Optional structured context.
tsepoch msServer-clock not available offline — uses local clock.
Audit writes are fire-and-forget and never block the UI. A failed write is swallowed silently to avoid cascading errors in a forensic context.

18 · Offline mode

ATLANTIS is built for air-gapped or unreliable-network environments. The first visit caches the entire bundle via a service worker; subsequent visits work without any network.

  • HTML is NetworkFirst — picks up new builds when online.
  • JS / CSS / fonts / workers are CacheFirst.
  • Data never leaves the browser — all IndexedDB.
  • Map tiles currently require network; the Geospatial View ships an offline-tile cache sketch (Dexie-backed tileCache store with cache / clear controls). Production MBTiles ingestion lands in Phase 4.
Clearing browser storage will wipe IndexedDB and force a full re-seed on next load. Export critical investigations before clearing.

19 · Glossary

EntityAny noun the platform tracks: person, organization, account, transaction, location, device.
RelationshipA typed, weighted edge between two entities.
EventA timestamped action: transaction, login, wire, alert, access, KYC check.
AnomalyA model-flagged event or pattern with a severity and human-readable reason.
InvestigationA case bundling entities, evidence, and notes.
RoleA named bundle of permissions assigned to an operator.
TickThe synthetic live-data heartbeat (every 2–5s) emitted by the tick worker.
SmurfingStructuring multiple small transactions to evade reporting thresholds.
LayeringShuffling funds through intermediaries to obscure origin.
